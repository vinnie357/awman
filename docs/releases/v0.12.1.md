# Downstream candidate v0.12.1

This is a candidate release of the `vinnie357/awman` fork, based on upstream
AWMan `v0.12.0` at commit `c730732b`. It is not an upstream AWMan release and
has not been published or tagged yet.

The candidate adds the opt-in startup-gate protocol needed by an external
orchestrator to prepare a group of agent containers before releasing any
agent. The CLI flags and shared wrapper establish the protocol surface; they do
not by themselves qualify the stricter split-control orchestrated Apple launch
path. The guarded `8fe0d4cc` revision still rejects that path before container
launch. Ungated and legacy gated launches retain their existing behavior.

Docker and Apple Containers share the legacy gated wrapper. A future qualified
split-control profile is intentionally narrower: command-mode Apple Containers
with validated controls, trusted image and runtime-user inspection, exact
container identity, and application-owned retention. Docker, sandbox, ACP,
remote, and TUI paths remain unsupported for that profile and must reject it
instead of silently downgrading it. The control protocol keeps host and guest
ownership checks separate so UID/GID remapping on Apple mounts does not weaken
either boundary.

Before this candidate can become a release, the fork still requires its full
local, runtime, remote, and independent review gates. Split-control Apple
support additionally requires a real Apple Containers qualification of the
exact rebuilt artifact. A future tag and release assets must be built from that
reviewed commit. Upstream `v0.12.0` does not provide the startup-gate extension.
