# v0.11.2 — release vehicle for the unreleased credential-delivery fix

**This is not an upstream release.** It is a build of `prettysmartdev/awman`
`main` at commit `9f63d915`, tagged in this fork solely so a downstream
consumer can install a binary containing a fix that upstream has written but
not yet released.

**No code is patched in this fork.** The tree at this tag is upstream `main`
verbatim, plus this notes file.

## Why

Upstream v0.11.1 delivers the Claude OAuth credential to the agent container
as an environment variable. On the `apple-containers` runtime, Apple Container
serializes the resolved value into the container's persisted configuration
(`config.json` and `runtime-configuration.json`, mode 0644), where it is
readable by any process running as the user, and it survives container exit.

Upstream `main` already fixes this (work item 0107): under `auth: keychain` on
container-class runtimes, the credential moves to a staged file mounted
read-only, and `AgentCredentials.env_vars` is forced empty so the token cannot
ride an `-e` alongside it. That change is 23 commits past the v0.11.1 tag and
has not been released.

## Verified before tagging

Same host, same command, same sampler (Apple Container CLI 1.3.1, M4):

| build | env names in persisted container config | token |
|---|---|---|
| v0.11.1 | `DEBIAN_FRONTEND, HOME, PATH, CLAUDE_CODE_OAUTH_TOKEN` | present |
| this tag | `PATH, DEBIAN_FRONTEND, HOME` | absent |

The agent still authenticates normally; mounts include
`/home/awman/.claude` and `/home/awman/.claude.json`.

## Retire this tag when

Upstream cuts a release containing WI-0107. Move the pin back to
`prettysmartdev/awman` at that point.

Note: the binary reports `awman 0.11.1`, because upstream has not bumped
`Cargo.toml` on `main`. Do not use `--version` to tell the builds apart —
check the env names on a live container instead.
