# AWMan v0.11.3 - vinnie357 fork

This release follows the `vinnie357/awman` fork's 0.11.x version line and
incorporates work based on upstream AWMan 0.12.0. The binary identifies this
fork release as `awman 0.11.3`.

- Adds opt-in startup-gate controls for external orchestrators and native print
  and session-resume command surfaces.
- Includes captured project-input proof, isolated native SDK settings and
  authentication state, and conservative launch retention and recovery.
- Preserves separate ownership of project inputs, writable SDK state,
  child-process retirement, and uncertain publication or cleanup.
- Keeps non-interactive command stdio separate from interactive PTY handling.

## Fixes

- Interactive `awman exec` now prints all of the agent's output before it
  returns. Before this fix, the last lines could be lost.
- When a launch fails after the agent process has started in a terminal (PTY),
  awman stops the process and then closes the terminal. The process now exits
  and is cleaned up instead of hanging.
- Cancelling a launch, and retrying a retained launch, now wait for the agent
  process to finish starting, for up to the operation's deadline.
- Cleanup of a retained launch now stops at its deadline, even while resources
  are still being destroyed.

## Known limits

- The output fix covers interactive `awman exec` only. Non-interactive CLI
  output and Docker attach do not wait for output to finish, so they can still
  lose the agent's last output.
- If awman cannot set up its launch-retention registry, a launch that fails
  after the agent process starts is not stopped. This happens only when that
  setup fails.
- No CI job runs the test suite on macOS. The macOS fixes in this release were
  verified locally.
- When a background process still holds the agent's terminal, interactive
  `awman exec` and a workflow step can wait up to about 4 seconds for the
  final output before they continue.

External startup control, including split-control orchestrated Apple launch,
is enabled as an experimental opt-in path. This release does not certify every
provider/runtime combination. The separate native Codex auth and main-execution
paths remain disabled in production pending qualification. Existing launch,
receipt, ownership and permission checks remain enforced.
